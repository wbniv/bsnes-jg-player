How to read it

Each tile is one ROM. The area is proportional to exact file size, so a 4 MiB ROM occupies 128 times the area of a 32 KiB ROM. Category clusters give the map a useful hierarchy; tile color repeats the category key.

Group by selector

Category
Default; curated semantic tags, plus Other builds
Build family
Group suffix and naming variants together
Size band
Group into <64 KB, 64–256 KB, 256–512 KB, and ≥512 KB
Area
Always the individual ROM’s exact byte size
List
Alternate searchable rows for precise text navigation

Interaction and data

  • Select a category or search to focus the corresponding tiles. Search autocompletes titles and filenames as the remote keyboard is used; Backspace removes only the typed prefix.
  • Focus a tile to reveal its title, exact filename, and size; Select loads it from the detail panel.
  • Current build size mix: 436 ROMs under 64 KB, 19 between 64–256 KB, none between 256–512 KB, and 64 at least 512 KB.
  • Unclassified ROMs remain in Other builds; category tags never determine whether a file is included.

Catalog-size behavior

How the treemap adapts

At runtime, derive labels and navigation from the loaded catalog count. The rectangle area always represents the individual ROM’s byte size; the four counts below are checkpoints for the same screen.

1 ROM

Show one full-area tile. Hide the group selector and category legend.

10 ROMs

Show ten readable, accurately sized tiles with inline names and sizes.

100 ROMs

Cluster by category, label tiles that fit, and expose every title by focus, search, or the list view.

1,000 ROMs

Keep all 1,000 tiles in the map; label only large rectangles. Category zoom, search, and a keyboard-accessible list provide exact navigation.

What stays constant: changing Category / Build family / Size band never changes the size-to-area relationship.
